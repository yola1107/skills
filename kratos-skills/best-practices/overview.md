# 交付复核

按本次影响选择证据，并完成仓库规定的必需检查；命令与环境沿用项目约定。代码、依赖和环境未变时复用已有结果，通过后仅因新增改动、失败或证据缺口补查。

| 改动 | 验收重点 |
| --- | --- |
| 业务与存储 | 相关调用方、金额与权限、错误身份和恢复；查询失败不能被当成缺行后继续写入 |
| 事务与并发 | 验证本次涉及的并发上限、取消、释放或竞争行为；涉及数据库事务或锁时，用目标数据库验证受影响的隔离、锁、幂等、回滚与提交未知，内存替身不能替代 |
| 协议与中间件 | 实际注册路径、字段与错误映射；签名入口覆盖原始 body、header、path/query、签名输入、成功/失败与新增拒绝响应 |
| 资源与生命周期 | 覆盖本次受影响的部分构造失败、启动失败、正常停止、取消/等待和关闭顺序；实际涉及的 Wire cleanup、客户端 Close 或 telemetry shutdown 须有执行证据 |
| 生成与依赖 | 受影响的输入、产物、调用方及实际工具版本；版本规则见[版本基线](../references/version-baseline.md)，升级时再检查受影响的依赖树 |

存在 endpoint 提前监听、启动 hook 或注册器时，覆盖相应早期失败与 transport 清理，见[装配边界](../references/architecture-patterns.md)。分层与转换也按该专题复核，避免每层复制完整测试矩阵。

配置改动保留严格校验与脱敏；schema 更新走项目授权的安装或迁移入口。涉及镜像时核对固定版本或 digest，以及证书、时区、用户和文件需求；涉及容量或性能时用预算与测量验收。

交付说明行为变化、实际检查、结果和未验证项。文档核验、示例编译、单元测试与真实集成验收分别说明，不能相互替代。
