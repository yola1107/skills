# Go 等价改写的前提

SKILL.md「写法」中的改写，只有满足这里列出的前提才算等价改动。前提不满足或无法确认时，按 SKILL.md「改动分类」处理。章节按「写法」的类别排列（注释类没有额外前提），最后一节是验证陷阱。

## 冗余

- **删除调用或计算**：读过被调函数的实现，确认没有副作用。
- **删除未使用的声明**：查清所有引用，包括其他构建标签下的文件。
- **删除包级变量**：初始化表达式没有副作用。`var _ = register()` 即使无人引用，也会在包初始化时执行。
- **删除常量**：检查整个常量块的 `iota` 和省略表达式的后续常量。`const (unused = iota; Code = iota)` 删除 `unused` 后，`Code` 从 1 变成 0。需要保持取值时改用 `_` 占位。

## 控制流

- **if-else 链改为 `switch`**：原分支里的 `break` 跳出的是外层循环，移进 `switch` 后只跳出 `switch`，含 `break` 的分支保持原样。比较对象是函数调用时，原链每个分支各调用一次，`switch` 只调用一次，同样保持原样。
## 作用域

- **放进 if/switch 初始化语句**：初始化表达式没有副作用，它读取的状态在原位置与新位置之间没有被修改。

## 显式

- **去掉命名结果**：`defer`/`recover` 读取或修改返回值时保留。
- **去掉 `_ = x`**：只去掉函数体内的占位赋值；包级的编译期断言 `var _ I = (*T)(nil)` 保留。
- **删除同类型转换**：只适用于整数、字符串等非浮点、非复数类型；类型参数要能排除浮点和复数。以下转换有实际作用，保留：
  - 作用于无类型常量的转换决定运算类型：`float64(1)/3` 得 0.333，去掉转换后 `1/3` 得 0。
  - 浮点、复数表达式外的同类型转换强制舍入，阻止编译器融合乘加：`float64(x*y) + z` 与 `x*y + z` 的结果可能不同（arm64 默认融合，amd64 在 `GOAMD64=v3` 下融合）；`complex128(...)` 和实例化为浮点的类型参数 `T(x*y)` 同理。

## 命名

- **查引用**：除标识符本身，还要搜它的字符串形式、struct tag、模板引用，以及其他构建标签下的文件。
- **字段改名**：未导出字段的名字会出现在 `%+v`/`%#v` 的输出里，检查打印该结构体的日志。
- **方法改名**：确认方法不用于满足接口或运行时类型断言。`x.(interface{ reset() })` 在方法改名后静默失败，编译器不报错。
- **receiver 和局部变量改名**：确认方法体内没有同名标识符，也没有闭包捕获造成的冲突。

## 现代写法

- **语言版本**：默认是 `go.mod` 的 `go` 版本；文件带 `//go:build goX.Y` 时，该文件按对应版本处理。例如 `go.mod` 声明 `go 1.22`、文件带 `//go:build go1.21` 时，该文件仍使用旧的循环变量语义。
- **`interface{}` 改为 `any`**：作用域内的 `any` 必须是预声明标识符。存在 `type any = int` 时两种写法都能编译，含义不同。
- **改用 `slices`/`maps`**：替换排序时，相等元素的相对顺序也要一致；原来是稳定排序就用 `slices.SortStableFunc`。
- **`for i := 0; i < n; i++` 改为 `for i := range n`**：
  - `n` 在循环中不变。`range n` 只在进入循环前求值一次，`i < n` 每轮都判断：`n` 初值为 3、循环体执行 `n--` 时，原循环跑 2 次，改写后跑 3 次。
  - 循环体不修改 `i`。
  - `i` 的类型不变。`n` 是无类型常量时，`range n` 中的 `i` 是 `int`：原写法 `for i := byte(0); i < 10; i++` 中 `i` 是 `byte`，改写后变成 `int`。
- **删除 `v := v`**：
  - 循环变量由循环头部的 `:=` 声明。`for k, v = range` 仍复用外层变量，删除副本后闭包结果从 1 2 3 变成 3 3 3。
  - 循环体内既不给副本赋值，也不给循环变量赋值。
  - 副本声明之前没有对循环变量取地址，也没有在闭包中引用它：`p := &v; v := v; p == &v` 删除副本后，比较结果由 false 变为 true。
  - 副本直接写在该循环的循环体里，每次迭代只创建一次。副本位于内层循环中、或在 goto 回跳的代码中，且被取地址或被闭包捕获时，保留：外层 `for _, v := range` 套内层两次循环、内层 `v := v; ps = append(ps, &v)`，删除副本后不同指针从 4 个变成 2 个。

## import

- **调整顺序**：包初始化顺序由构建所用的工具链决定，与 `go.mod` 的 `go` 版本无关。Go 1.21 及以后的工具链按导入路径排序，import 顺序不影响初始化；项目仍用更早的工具链构建时，调整顺序列为待决。
- **别名**：`_` 和 `.` 导入保持原样。

## 验证

- **gofmt 与 CRLF**：Windows 的 CRLF 工作区里，`gofmt -l` 会报出所有文件。把文件转成 LF 副本，放到临时目录里检查。
- **gofmt 对齐**：删除声明块中的一行（包括注释行），可能让前后两段对齐区域合并，gofmt 会重排整块。必要时在原位置保留一个空行。
- **测试断言**：只打印、不断言的测试不能证明行为等价。
- **竞态检测**：涉及并发的改动跑 `go test -race`，它依赖 cgo；跑不了时在报告里注明。
- **浮点舍入**：是否融合乘加取决于目标平台，amd64 默认的 `GOAMD64=v1` 不融合，本机测试可能发现不了舍入差异；这类改动以本文件的前提为准。
