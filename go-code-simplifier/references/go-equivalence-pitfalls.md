# Go 等价改写的前提

涉及下面的改写时，先读对应小节并核对实际路径。这些是核对要点，不是对所有代码的固定扫描清单；无法确认等价时缩小改动或保留，并说明具体原因。检查通过只支持实际覆盖的行为。

## 控制流

- **反转 if/else 并提前跳出**：`if c { A } else { B }` 改为 `if !c { B; continue }` 后接 `A`，不能跳过本轮原本必做的收尾。函数里用 `return` 时，核对返回值及后续工作是否等价。末尾分支容易确认；存在共同后续语句时，保留它们在所有原有路径上的执行。
- **if-else 链改 `switch`**：只合并互斥的选择，不能将可能都执行的独立 `if` 合成单选分支。原分支里跳出外层循环的无标签 `break`，移进 `switch` 后只跳出 `switch`；保持退出目标。将重复比较中的函数调用移到 `switch` 判别式，会改变调用次数，须确认无副作用且值稳定。
- **提取函数或方法**：
  - 原代码中作用于原函数或外层循环的 `return`、`break`、`continue`，通过返回值带回，所有路径结果不变。
  - 块内赋值、块外还要读的变量（包括 `err`）作为结果返回；块内修改的外层变量，传指针或返回新值。
  - 移进新函数的 `defer` 在新函数返回时执行，比原来提前；`recover()` 只在被 `defer` 直接调用的函数中生效。
- **调整条件顺序**：`&&`/`||` 短路，交换后求值次数改变；保护后续访问的 nil 判断必须在前。

## 冗余

- **删除调用或计算**：确认没有可观察的副作用、panic 或阻塞；未使用的结果不代表产生它的求值可删除。合并重复调用还要确认两次调用之间结果不会改变，包括随机、时间、原子读取和可变状态。
- **删除未使用的声明**：查清所有引用，包括其他构建标签下的文件和字符串形式的引用。包级变量的初始化可能有副作用：`var _ = register()` 无人引用，也会在包初始化时执行。
- **删除常量**：同一常量块的 `iota` 会重新编号，需要保持取值时用 `_` 占位。
- **删除重复初始化**：两次初始化之间没有读取，也没有传给其他函数；第一次的表达式没有副作用。
- **保留**：包级的编译期断言 `var _ I = (*T)(nil)`。

## 作用域

- **移动声明（靠近使用或放进 if/switch 初始化语句）**：初始化表达式没有副作用，它读取的状态在原位置与新位置之间没有被修改。
- **改用 `:=`**：原代码给外层变量赋值、外层之后还要读它时，改成 `:=` 会声明新变量，外层保持旧值。
- **移进循环体**：值需要跨迭代保留，或被取地址、被闭包或 goroutine 捕获时，留在循环外。

## 错误处理

- **消除 nil 分支后直接返回错误**：原来 `if err != nil { return err }; return nil` 中，若 `err` 的静态类型是 `error`，直接 `return err` 保持 nil 语义。若是 `*MyErr` 等具体类型，nil 指针装进 `error` 接口后不等于 nil。一般的直接返回须逐个核对返回值的类型转换，以及中间日志、包装和其他副作用。
- **`==` 改 `errors.Is`、类型断言改 `errors.As`**：会匹配被包装的错误，范围变宽，不改。

## 返回值

- **去掉命名结果**：`func() (err error)` 与 `func() error` 类型相同。前提：
  - 没有 `defer`/`recover` 读写结果。
  - 裸 `return` 全部改成显式返回，返回的是该处结果变量的当前值。
- **删除结果**：调用方要同步修改；函数作为值传递或用于满足接口时不能删除。
- **去掉 `_ = x`**：只去掉函数体内的占位赋值。

## 命名

- **查引用**：除标识符本身，还要搜它的字符串形式、struct tag、模板引用，以及其他构建标签下的文件。
- **方法改名**：确认方法不用于满足接口或运行时类型断言。`x.(interface{ reset() })` 在方法改名后静默失败，编译器不报错。
- **字段改名**：未导出字段的名字会出现在 `%+v`/`%#v` 的输出里，检查打印该结构体的日志。
- **新名字**：不能与函数内之后还要用到的包名、内置名或外层变量同名。遮蔽同类型的外层变量时能编译通过，但读写对象变了。
- **合并重复调用为局部变量**：被调函数无副作用，两次调用之间返回值不变。

## 现代写法

- **语言版本**：根据 `go.mod`、文件构建约束与实际工具链确认文件的生效版本；`//go:build` 中的 Go 标签表示版本下界，不能把标签名称直接当作文件语言版本。具体规则见 [cmd/go 构建约束](https://pkg.go.dev/cmd/go#hdr-Build_constraints)。作用域内有自定义的 `any`、`min`、`max` 时不替换。
- **空集合写法**：`var s []T`、`[]T{}`、`make([]T, 0)` 的 `s == nil` 结果不同，JSON 编码分别为 `null`、`[]`、`[]`。值会被返回、序列化或比较时保持原写法。
- **`strings.Cut`**：未找到分隔符时返回 `s, "", false`，与原代码在这种情况下的返回值一致才能替换。
- **`min`/`max`**：浮点参数中有 NaN 时结果为 NaN，与手写比较不同。参数可能是浮点时保持原写法。
- **排序**：原来是稳定排序就用 `slices.SortStableFunc`；比较函数在相等时必须返回 0。
- **`for i := range n`**：`n` 和 `i` 在循环中不被修改；`i` 的类型变为 `n` 的类型，`for i := byte(0); i < 10; i++` 改写后 `i` 是 `int`。
- **删除 `v := v`**：文件生效版本为 1.22+，循环变量由循环头部的 `:=` 声明，副本声明之前没有对循环变量取地址或在闭包中引用。
- **删除类型转换**：核对操作数的类型、常量的默认类型与表达式运算规则。`float64(1)/3` 去掉转换后变成整数除法；浮点表达式外的显式转换还可能阻止融合乘加，需要保留舍入语义。

## import

- **调整顺序**：包初始化顺序由构建所用的工具链决定，与 `go.mod` 的 `go` 版本无关。Go 1.21 及以后的工具链按导入路径排序，import 顺序不影响初始化；项目仍用更早的工具链构建时，不调整顺序。
- **`import "C"`** 必须紧跟 cgo 注释，保持单独声明。

## 并发

- **在加锁的函数里调整控制流**：保持锁的获取与释放路径及被保护操作的边界。非 defer 解锁的路径不能通过新增退出绕过解锁；原代码已漏解锁的是缺陷，只报告。锁内的局部整理仍可进行，但须保持共享状态访问、副作用和同步关系。
- **删除临界区内的死计算**：结果确实未被使用且计算不影响状态、panic、阻塞或同步时可以删除；不能把计算或共享状态读取移出锁来缩短临界区。
- **改成 `defer mu.Unlock()`**：可能延长临界区并改变 panic 时的解锁行为；不能仅因代码更短就替换。
- **值接收者与指针接收者互换**：会复制 `sync.Mutex` 等字段并改变方法集，不改。
