# Go 等价边界

按本次候选涉及的变换读取对应小节。判断依据是实际实现与调用契约；可编译、名称像 getter 或结果未使用，都不能单独证明等价。

## 名称、类型与版本

- 按 [Effective Go](https://go.dev/doc/effective_go#names) 与 [Go Code Review Comments](https://go.dev/wiki/CodeReviewComments#variable-names) 在实际使用点判断名称：局部循环可用 `i`，无需 `sliceIndex`；包名、类型或接收者已说明的含义省去。名称已经清楚区分角色时就停止加长，避免堆叠修饰词或重复类型后缀；[接收者](https://go.dev/wiki/CodeReviewComments#receiver-names)通常用一两个字母的类型缩写，同类型保持一致。
- 改名核对作用域、遮蔽、闭包及引用。优先使用 `gopls rename`；文本或 AST 名称匹配不等于符号匹配。接口参数和结果名称可以清理，类型、数量、顺序及可变参数约定保持不变。
- 重命名后补查 tag、模板、字符串注册和反射引用；涉及其他平台或构建标签时补查对应配置。工具的未到达结果不能单独作为删除依据。
- 保持公开 API、接收者类型、方法集、类型别名身份及注册契约。公开符号在仓内没有调用方，不足以证明可以删除或改名。
- 保持具体类型、整数宽度和溢出、常量值及有类型／无类型属性。核对 typed nil 到 interface 的转换，不能仅凭类型兼容删除转换。
- 按目标模块版本判断语法和标准库支持；工作区工具链较新不代表可以提高最低版本。`go fix`、`modernize` 和 lint 建议逐项复审；清理不升级依赖或重组工作区。
- imports 按包的归属分组，遵循项目约定及主文的默认分组；格式工具的输出不能取代分组要求。按实际包名判断别名是否多余，路径末段与包名不同本身不要求别名；需消歧时保留别名。删除 import 前核对包变量、init、传递依赖和注册副作用，保留必要的 `_` 导入。

## 表达式、直返与存储删除

- 保持求值次数、顺序、条件执行和短路；保留时间、随机调用及浮点分组、NaN／正负零语义。变量移动前核对快照时点和跨迭代状态。
- 结果未读也须核对实际副作用，包括共享状态写入、外部调用、类型断言、索引检查和 nil 访问可能触发的 panic。删除冗余存储时保留必要求值。
- 字段只被初始化赋值不等于有读取用途；区分读取、赋值和注册。可重算的值仍可能是快照、缓存或恢复证据，按实际职责判断。
- 返回值默认明确写出；命名结果仅在 defer／recover 依赖它或有助于区分返回契约时保留，保留命名结果时仍默认列出返回表达式。直返须保持返回类型、转换、错误身份、错误链及优先级、失败时的部分值，以及 defer 读取或修改结果的语义。
- 忽略 error 先核对现有契约；修改已有错误文本或新增传播、包装、日志、重试、校验、recover 都是行为变化。删除包装须保留其错误转换、事务、同步及收尾职责。

下面在失败时丢弃部分值，不能机械改为 `return load()`：

```go
value, err := load()
if err != nil {
	return 0, err
}
return value, nil
```

defer 也可能依赖局部赋值，不能把这里的最后两行改为 `return work()`：

```go
func execute() error {
	var err error
	defer func() { record(err) }()
	err = work()
	return err
}
```

## 集合、结构体与共享

- 保持 nil、零值与已分配空集合的区别，以及 map 缺失与零值、slice 长度和容量、元素顺序与重复项；不为风格统一改变序列化结果。
- 保持共享、别名及所有权，不能用副本替代原对象，或反过来；不复制带锁的值。
- 拆分结构体字段或改为具名初始化时，保留字段顺序、类型、tag、嵌入关系及各值的求值顺序；不为排版重排布局、增改标签或扩大公开接口。

## 控制流、同步与函数提取

- 默认赋值仍在 guard 前执行；移除 `else` 核对 if-init 变量作用域。独立分支与互斥分支保持原执行关系。
- `continue`／`break`／`return` 保持原退出范围；核对循环尾部、post、label 和 switch／select 的退出目标。
- 给复杂条件命名或改为 `switch` 时，保持求值次数、顺序和短路。把有副作用的调用、索引、解引用和可变状态读取留在原执行条件下。
- 保持锁范围、顺序及锁内调用；保留取消、goroutine／channel 生命周期、channel 收发与背压及资源创建、回滚和关闭时点。
- `defer cleanup(value)` 登记时求值，闭包可能执行时读取；保持捕获及执行顺序、panic／recover。循环体移入 helper 可能提前执行 defer，提取前核对解锁、关闭和回滚时点；保留 `recover` 与被延迟执行函数的直接调用关系。
- 提取或内联后逐调用点复核：参数的副作用按原次数执行，指令与注释保留原作用位置；工具生成的结果也逐项审查。
- 同形逻辑合并须有相同输入、失败、顺序和业务契约；敏感调用不妨碍周围已证实等价的清理，保留理由落到具体变换。

## 测试与检查

- 清理测试时保留输入、断言、失败／跳过条件、setup／cleanup、同步及 Example 输出注释。仅为真实行为风险补用例，不为命名、排版或等价直返镜像编写测试，也不扩大生产接口或增加全局开关来方便测试。
- 按实际改动路径检查测试覆盖；存在行为风险且缺少覆盖时，先用最小行为测试固定当前返回值、失败路径和副作用，再重构。覆盖率不能证明等价，现有异常规则照常保留。
- 不熟悉的测试运行前检查 TestMain、包初始化、环境变量、fixture 和清理行为，确认外部资源隔离。
- 多 module 分别确认检查覆盖。跳过用例或交叉编译不算执行测试；工具或平台不可用时说明缺口。检查失败时对照基线区分新增回归与既有问题，只修复本轮引入的回归。
