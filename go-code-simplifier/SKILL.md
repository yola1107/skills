# Go Code Simplifier

按 Go 官方风格清理 Go 代码，目标是读起来更直接、写法更显式、冗余更少，同时外部行为保持不变。取舍顺序是：**行为等价 > 清晰 > 显式 > 简单 > 短**。这里的清理就是 Fowler 意义上的 refactoring，每处改动都要说得出等价理由。

## 风格依据

以 [Effective Go](https://go.dev/doc/effective_go)、[Go Code Review Comments](https://go.dev/wiki/CodeReviewComments) 和 [Go Doc Comments](https://go.dev/doc/comment) 为准；项目规则（AGENTS.md、CLAUDE.md、lint 配置）可以在此基础上补充或明确覆盖。能否使用新语法和标准库 API，以 `go.mod` 声明的 Go 版本为准。排版交给 `gofmt`。

## 写法

- **控制流**
  - 先处理错误和边界，用提前 return/continue 退出，主流程保持在最少的缩进层级；分支以 return、break 或 continue 结束时，去掉后面的 else。
  - 对同一个变量反复比较时，改用 `switch`。
  - 三个及以上的条件组合，提取成具名布尔变量；只提取无副作用的简单判断，函数调用留在原表达式里，保持短路求值。
- **声明与作用域**
  - 零值初始化用 `var x T`，非零初始值用 `:=`。
  - 声明靠近首次使用的位置；只在单个分支内用到的值，放进 if/switch 的初始化语句。
  - 内层用 `:=` 遮蔽了外层同名变量时，给内层变量改名。
- **显式**
  - return 时写出返回值，不用裸 return。命名结果只在需要区分同类型的多个返回值，或 defer/recover 要修改返回值时使用。
  - 复合字面量写字段名。
  - 去掉 `_ = x` 这类占位赋值，在接收处直接用 `_`。
  - 删除冗余的类型转换。
- **命名**
  - 使用 MixedCaps，缩写词整体大写或整体小写（`ID`、`URL`）。
  - 名字长短与作用域相称，`i`、`err`、`ctx` 这类惯用短名保留。
  - 按业务角色命名，同一概念始终用同一个叫法，不重复包名、类型名已经表达的信息。
  - receiver 用类型名的 1–2 个字母缩写，同一类型的所有方法保持一致，不用 `this`/`self`。
  - 布尔字段加 `is`/`has`/`can` 前缀。
- **现代写法**（按 `go.mod` 版本）
  - `interface{}` 改写为 `any`。
  - 计数循环改写为 `for i := range n`（Go 1.22+）。
  - 删除循环变量的拷贝 `v := v`（Go 1.22+）。
  - 手写的查找、排序循环，在语义完全相同时，改用 `slices`/`maps` 包。
- **import**：对本次改动到的文件，按标准库、本项目包（以 `go.mod` 的 module 路径为前缀）、第三方包分三组，组间空一行；只在名字冲突时使用别名。
- **冗余**：删除被注释掉的代码、未使用的声明，以及计算后不再使用的结果；删除多余的 `break`、`return` 和类型转换。
- **注释**
  - 删除复述代码的注释，修正与代码矛盾的注释；保留解释原因、契约、工具指令和阶段分隔的注释。
  - 新写或修正的 doc comment 以被声明的名字开头，写成完整的句子，内容要超出签名本身已经表达的信息，例如 `// Bet 校验下注状态后扣款并广播下注消息。`。
  - 注释只描述代码当前的行为，不补写代码里没有依据的意图；疑似缺陷写进报告。

## 适度

- 一个有意义的中间变量或小函数，能给某个步骤起名字，便于阅读和调试，应当保留。
- 不为减少行数而压缩代码：把多个操作塞进一行、层层嵌套调用、把职责不同的逻辑合并到一起，都会比原来更难读。
- 只有输入、失败路径、执行顺序和职责都相同时，才合并重复的逻辑。
- 已经清楚的代码不动。

## 可观察行为

改动前后，以下内容保持一致：

- 返回值、错误身份与文本、失败路径的部分返回值、panic。
- 对外调用（RPC、数据库、消息推送、定时任务）的参数、次数和顺序。
- 日志的级别、文本和字段，包括写错的格式串。
- 锁的对象、临界区范围和加锁顺序；goroutine、defer 和资源的生命周期。
- 导出标识符、接口签名、struct 字段名与 tag，以及通过反射、字符串注册或配置引用的名字（路由、RPC 方法名、表名）。
- 求值次数与顺序、短路、nil 与空集合、切片的共享与容量。

## 改动分类

每个候选改动归入以下三类之一：

- **等价改动**：给得出等价理由，就直接实施。理由有三种：
  - 编译器保证：例如删除未使用的声明、删除冗余的类型转换。
  - 局部改写：例如控制流、作用域、返回值的改写，以及对未导出符号或 receiver 的改名，前提是返回值、短路和执行顺序不变，所有引用都已查清。
  - 已核实：删除调用或计算之前，读过被调函数的实现，确认它没有副作用。
- **待决改动**：有收益，但需要人来判断，只列出、不实施：
  - 改动导出名、带 tag 的字段名、错误文本，或通过反射、字符串引用的名字；
  - 删除薄包装，或提取跨职责的函数；
  - 改动临界区内执行的代码；
  - 依赖运行时不变量的改写（例如假设两个 id 总是相等）；
  - `go.mod` 版本低于 1.21 时调整 import 顺序（会影响包初始化顺序）；
  - 看起来多余、但可能有作用的代码，按 Chesterton's fence 处理（例如空的加锁/解锁对）。
- **发现**：缺陷、竞态、安全问题、被丢弃的 error、日志格式错误。代码保持原样，写进报告。

## 流程

改动留在工作区，由用户审阅 diff 后自行提交；skill 不暂存、不提交，也不推送。

1. **范围与基线**
   - 未指定范围时，处理当前的改动；指定了文件或目录时，覆盖其中全部手写的 Go 代码和测试，跳过 vendor 和生成的代码。
   - 查看 `git status`。工作区已有用户改动时，保留这些改动，并在报告里列出这些文件，方便用户审阅时区分。
   - 从仓库里找验证入口：Makefile、CI 配置、lint 配置、AGENTS.md、CLAUDE.md。
   - 运行并记录：目标包及调用方所在包的 `go build`、`go vet`、`go test`。跳过需要连接外部网络或数据库的测试。如果仓库已经配置了 staticcheck 或 golangci-lint，也一并运行并记录。缺少的工具只记录，不安装。
   - 完成标准：每条验证命令的基线结果都已记录，已有的失败标为既有失败。
2. **通读与分类**
   - 按文件读完整的函数，弄清每条路径的返回值、副作用、锁和调用顺序。
   - 改名、删除或修改签名前，先查清所有引用：有 gopls 就用 gopls，否则用 `rg -w` 或 `grep -rw` 搜标识符，再搜它的字符串形式、struct tag 和模板中的引用。
   - 完成标准：范围内的每个文件都已读完，每个候选改动都已归入三类之一。
3. **按类实施等价改动**
   - 顺序依次为：冗余、控制流与作用域、显式、命名、现代写法、import 与注释。
   - 每完成一类，重跑第 1 步的全部命令，结果与基线一致才进入下一类；不一致时，修正或撤回这一类的改动。
   - 改写纯函数内部逻辑前，先补 characterization test，固定现有的输出；这些测试随改动一起保留。
   - 完成标准：所有类别都已通过验证。
4. **复核**
   - 通读完整 diff，确认每处改动都有阅读收益，并能重新说出等价理由；说不出来的撤回，改列为待决。
   - 结构改动可能带出新的清理机会，只在受影响的函数内处理。
   - 完成标准：每处改动都有收益，也有等价理由。
5. **报告**：按下方模板交付。

## 验证陷阱

- 在 Windows 的 CRLF 工作区里，`gofmt -l` 会把所有文件都报出来。要先把文件转成 LF 副本，放到临时目录里再检查。
- 删除声明块中的一行（包括注释行），可能让前后两段对齐区域合并，导致 gofmt 重排整块。必要时在原位置保留一个空行。
- 改 receiver 名或局部变量名之前，确认方法体内没有同名标识符，也没有闭包捕获造成的冲突。
- 只打印、不做断言的测试，不能证明行为等价。
- 涉及并发的改动要跑 `go test -race`，它依赖 cgo；跑不了的话，在报告里注明。

## 报告模板

```markdown
## 结果
<范围、最终验证结论；工作区原有的用户改动（如有）>

## 已实施（按类）
- <类别>：<文件> — <改动>；等价理由：<编译器保证／局部改写／已核实 …>

## 待决
- `<文件:行>` <建议改动> — <需要判断的原因>

## 发现（未修改）
- `<文件:行>` <现象> — <影响>

## 验证
- <命令>：基线 <结果> → 结束 <结果>
- 跳过：<检查> — <原因>
```
