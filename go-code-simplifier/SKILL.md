# Go Code Simplifier

简化现有 Go 代码，使其清晰、惯用、易维护。**安全（行为等价） > 清晰度 > 简单 > 短**。主动检查完整范围，针对具体阅读障碍选择改动，已清晰的代码保留。

## 范围

用户指定目录时，检查其中全部自行维护的手写 Go 文件，包括 `_test.go`，不限于 git diff 或少量容易修改的函数；未指定范围时聚焦本轮改动。默认跳过 `vendor/` 和第三方代码副本，除非用户明确指定；生成文件只通过源或生成流程更新。

清理只授权指定范围内的本地修改，不包含无关修复、提交或发布。用户仅要求评审时保持只读。

## 项目适配

- 项目明确规则、格式与 lint 配置及既有约定优先于下列风格偏好；行为等价始终是前提。项目没有额外约定时采用 Go 惯用写法。
- 按目标文件所属的 `go.mod`、现有 `go.work` 和 CI 配置确认模块边界、支持的 Go 版本及构建条件。本机或工作区工具链较新，不代表目标模块可以使用更高版本的语法或标准库 API。
- 涉及现代化替换时，同时核对版本支持和等价边界；`go fix`、`modernize` 或 lint 的建议仍需逐项复审。清理不提高项目最低 Go 版本、不升级依赖，也不重组模块或工作区。

## 清理重点

- **空行与注释：** 删除函数体首尾及同一处理阶段内无意义的空行，合并连续空行，保留逻辑阶段和声明组之间的分隔。删除复述显然代码的注释和废弃代码注释，修正描述错对象或已过时的注释。保留原因、契约、版权，以及 `//go:`、`//nolint` 等编译、生成、检查指令及其作用位置；Example 的输出注释属于测试断言。
- **命名：** 逐函数检查接收者、参数、局部变量及必要保留的命名返回值，覆盖方法、接口方法及函数类型签名，大函数也完整检查。优先修正误导或含糊的名称；读完变量的全部赋值与用途后，选择上下文中简短且无歧义的名称，使其在每个使用点都准确。名称详略与作用域及声明到使用的距离相称。多个同类型值突出对象、来源、状态或单位，避免用序号掩盖不同角色；集合名优先说明存放什么，索引已明确时省去重复后缀，确需说明或区分索引时可用 `ByID`、`ByName`。使用 MixedCaps，常见首字母缩写保持一致，如 `userID`、`HTTPClient`；保留 `i`、`n`、`err`、`ctx` 等惯用局部名，避免生造缩写与重复的类型信息。局部名称不必沿用协议字段或数据库列名的拼写。将 `this`、`self` 改成简短的类型相关接收者，同类型在范围内一致；改名前核对作用域、遮蔽、闭包及引用，不做无必要的跨文件或公共 API 改名。
- **声明：** 单个显式初始化的局部变量通常用 `:=`，零值声明用 `var`；相关或同阶段的相邻变量可保留紧凑的 `var (...)` 分组。初始化已确定同一类型时省略重复类型，分组无需为此拆散。变量在所属处理阶段、靠近首次使用处声明；同一临时变量被用于不同角色时，核对读写依赖后按阶段拆分，使名称与各自职责对应。移动或拆分前核对求值时点、副作用、遮蔽和跨迭代状态。
- **中间变量：** 删除仅作转抄的变量、写后未读或随即被覆盖的赋值、确实多余的类型转换，保留右侧副作用。保留表达业务概念、固定求值时点及影响类型或转换的声明；费解的条件或计算可引入有意义的局部名，保持求值次数、顺序和条件执行。
- **控制流：** 错误和边界 early return，循环跳过路径用 continue，删除终止分支后的多余 else，让主路径平直；保留更清晰的并列分支。移除 else 前核对 if-init 变量的作用域。简化布尔转抄与冗余比较，保持结果类型、短路和分支副作用。默认赋值仍在 guard 前执行。只有后续迭代确实无需执行时才 early break，核对循环尾部、post、label 和 switch/select 的退出目标。
- **返回值与 error：** 有返回值的函数默认不命名结果、不用裸 `return`；仅在 `defer`/`recover` 依赖结果变量，或名称确实帮助理解返回值契约（如区分多个同类型结果）时保留。无返回值函数保留用于提前退出的 `return`。类型及转换相同时，末尾无额外处理的转抄和 error 检查改为直接返回；保留前置错误 guard、错误身份、部分返回值及 defer 读取的局部赋值。现有忽略 error 先核对契约，确认可忽略才显式 `_ =`；新增传播、包装、日志、重试、校验或 recover 属于行为变化。
- **冗余结构：** 删除死代码、重复判断和无读取用途的私有字段。字段仅被初始化赋值不等于有用途；删除冗余存储时保留必要的类型断言、求值与副作用。可推导的值仍可能承担快照、缓存或恢复证据，不能仅因能够重算就删除。核对引用、接口、嵌入和构建条件；反射、布局、序列化或注册需有实际使用依据才构成保留理由。
- **重复与包装：** 同形代码只有在输入、失败、顺序和业务契约一致，且属于同一责任方时才合并；不把局部业务规则搬到通用包。删除包装前核对错误转换、日志、同步、事务、资源收尾、公开兼容和注册职责；保留能表达业务概念、降低调用方理解成本的 helper。新 helper 或接口须消除当前重复、隔离明确职责或降低调用方复杂度，不为假设扩展、mock 便利、函数长度或复杂度分数新增层次。必要的内部迁移同步调用方、测试和文档。
- **一致性：** 签名尽量单行；参数较多或过长影响阅读时换行，不为单行缩写名称或牺牲清晰度。测试同样清理命名、声明和嵌套；不为重复字面量机械提取常量。
- **imports：** 按项目约定分组；未约定时分为标准库与其余导入两组，中间空行，组内按格式工具排序。去掉不必要的别名；包名与路径末段不同或需消歧时保留别名。删除无用导入前确认初始化、注册等副作用；保留必要的 `_` 导入，不能只因无符号引用就删除。

## 等价边界

- 保持求值次数与顺序、短路和独立分支、时间/随机调用、浮点运算分组及 NaN／正负零语义、整数宽度与溢出、常量值及有类型／无类型属性、具体类型及 typed nil 到 interface 的转换；可编译不代表直返等价。
- 保持错误身份、错误链及优先级、部分返回值、panic/recover；保持 nil／零值／已分配空集合、map 缺失与零值、slice 长度容量、共享与别名、元素顺序及重复项。
- 保持接收者类型、方法集及类型别名身份、锁范围与顺序、锁内调用、defer 捕获和执行顺序、取消与 goroutine/channel 生命周期、资源创建/回滚/关闭；不复制带锁或所有权的值。`defer cleanup(value)` 在登记时求值，闭包可能在执行时读取；将循环体移入 helper 可能提前执行 defer。提取函数须核对解锁、关闭和回滚时点，以及 channel 收发、关闭与背压。
- 保持公开 API、接口契约、协议、默认值、序列化、持久化、外部 I/O 和日志。公开符号在仓内没有调用方，不足以证明可以删除或改名。接口参数与结果名称不参与类型匹配，可按上述规则清理；方法集及参数/结果的类型、数量、顺序和可变参数约定保持不变。增删 import 核对包变量、init、传递依赖及注册副作用。业务语义按实际调用契约判断，不按名称猜测。
- 测试保持输入、断言、失败/跳过条件、setup/cleanup 和同步语义。性能优化、业务修复、依赖升级和架构重设计留在本任务之外。以上约束优先于风格建议和自动修复。

### 直返反例

下面的错误分支会丢弃失败时的部分值，不能机械改成 `return load()`；直返还须核对失败返回值、返回类型及转换：

```go
value, err := load()
if err != nil {
	return 0, err
}
return value, nil
```

即使没有命名结果，defer 闭包也可能依赖局部赋值；这里不能把最后两行改成 `return work()`：

```go
func execute() error {
	var err error
	defer func() { record(err) }()
	err = work()
	return err
}
```

## 工作方式

1. 读适用项目规则，检查 `git status --short`、相关暂存及未暂存 diff，并阅读范围内的未跟踪文件，以包含用户修改的实际状态为基线。列全目标文件，阅读函数、测试及必要调用方，找出上述各类候选及具体收益，如消除歧义、减少回读或降低嵌套。删除或合并前理解现有职责、失败路径及限制；原因仍不明确时按需查 Git 历史，没有历史不妨碍依据当前契约作出判断。
2. 按职责连贯的批次、符号作用域和完整语法结构集中修改，有依赖的改动一起完成。改名优先使用可用的符号重命名工具（如 `gopls rename`），预览变更范围；自行批量编辑时，仅匹配文本或 AST 名称不足以区分符号，须逐处确认改名后的引用仍指向原声明。内外层同时使用的不同对象用不同名称，重点检查嵌套循环与闭包的捕获、遮蔽；同步更新引用，保持字符串内容。继续覆盖整个指定范围；敏感调用不妨碍其周围已证实等价的局部清理，无法确认的候选保留并记录具体原因。
3. 对照修改前后的完整函数和使用点，分别审查可读性与行为等价性：名称能否更快区分角色，声明是否仍体现分组与处理阶段，控制流是否更易追踪；再核对调用链、失败路径和边界。只有写法变化而无阅读收益，或等价性仍有疑点时，局部撤销本轮改动并保留用户修改。再逐文件扫查候选，落实遗漏；已清晰的文件可以零修改。
4. 对改动的 Go 文件运行 `gofmt`，按所属 module 或现有工作区的仓库入口运行受影响测试和 `go vet`；多 module 分别确认覆盖，变更涉及构建标签或平台时补相应检查，交叉编译或跳过用例不算执行测试。运行不熟悉的测试前检查 `TestMain`、包初始化、环境变量、fixture 和清理行为，确保外部资源隔离。改动涉及并发访问、同步或退出协作时补 `-race`；工具或目标平台不可用时说明验证缺口。检查失败时，必要时对照修改前基线区分新增回归与既有问题，只修复本轮引入的回归。复用现有测试和本轮有效结果，仅因改动、失败或明确风险追加验证，不逐次编辑重复跑整套检查。纯命名、格式和等价直返不另建测试；仅为实际行为风险补用例，不增加生产全局开关或扩大接口来方便测试。独立复核遵循项目要求。
5. 全部目标文件已检查、候选已处理或说明具体保留理由，且适用检查通过后结束。简述有效改进、重要保留项及实际验证；受阻时明确缺口，不以测试通过、lint 通过或改动数量代替完成判断。
