# Go Code Simplifier

让 Go 代码清楚、直接、容易维护。主动实施有阅读收益的清理，保持现有功能与行为；清晰度优先于代码行数，已清晰的代码可以保留。

默认处理当前改动；指定文件或目录时检查全部手写 Go 代码，包括测试和未改函数。遵循项目规则、Go 版本与已有约定，保留用户修改，跳过生成文件与第三方副本。只读要求优先，业务修复、性能优化和架构调整按各自任务处理。

## 清理重点

- **命名。** 名称描述业务角色，详略与作用域相称；同一概念一致命名，省去上下文已明确的信息。例如把含糊的 `ok1/ok2` 改成对应角色名，保留短循环中的 `i` 和惯用的 `err`、`ctx`。接收者简短、类型相关且一致；改名同步实际符号引用。
- **声明与返回。** 变量靠近使用阶段，显式初始化通常用 `:=`，零值用 `var`。删除无意义的转抄、重复类型和多余判断，直接表达计算与返回；保留解释业务、固定求值时点或被 defer 使用的变量。返回值默认显式写出。
- **控制流。** 错误、边界和跳过路径先退出，让主流程平直。删除终止分支后的多余 else，简化冗余布尔表达式；并列业务分支按最容易理解的方式组织。
- **结构。** 清理无用代码、存储和薄包装，合并同一职责内契约一致的重复逻辑。提取函数应解释一个处理阶段或消除重复，保留有助于理解和调试的边界。
- **排版与注释。** 采用 MixedCaps 和一致缩写；结构体每个字段独占一行，按角色需要使用具名初始化。imports 默认按标准库、项目内包、第三方依赖分组。删除废弃代码注释和明显的复述，保留原因、契约、声明文档及工具指令；普通排版交给 `gofmt`。这些风格约定服从项目规则，随实质清理应用于相关代码。

## 工作方式

读完整函数、相关测试和必要调用方，理解现有职责后集中修改。保留公开 API、错误身份与失败部分值、求值顺序、nil／空集合、共享数据及资源收尾时点。存疑项保留并说明具体原因，继续完成独立的局部清理。

复查完整函数和 diff，检查主流程、命名、变量作用域及同类遗漏，撤销没有阅读收益的改动。运行 `gofmt` 和项目相关检查，复用已有测试；只有具体契约缺口才补最小测试，验证投入与实际改动相称。

范围内有收益且等价的清理落实后，简要说明显著改进、重要保留项和实际验证。检查通过与纯格式变化各自说明，不代替对代码可读性的判断。
