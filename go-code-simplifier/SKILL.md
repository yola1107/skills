# Go Code Simplifier

把 Go 代码整理得更容易理解和维护，完整保留现有功能与行为。优先选择清楚、直接的表达，不追求最少行数。

## 清理原则

1. **保持行为。** 保留输出、错误、默认值、日志、数据共享和执行顺序。判断风险时针对具体转换；一个函数业务复杂，不代表其中的局部结构不能简化。有等价性疑问时，按需查阅 [Go 等价边界](references/go-equivalence.md) 的相关小节。
2. **遵循项目约定。** 按适用的 AGENTS.md／CLAUDE.md、Go 版本及格式配置处理。项目没有规定时使用下述默认风格。
3. **改善清晰度。** 拉平错误和边界分支，让主流程直接可读；缩短临时变量的作用域，删除无意义的转抄、判断、存储与包装；合并同一职责内契约一致的重复逻辑；修正含糊命名和误导注释，移除废弃代码注释。
4. **保持适度。** 保留能解释业务、组织职责或帮助调试的变量和抽象。提取函数应让处理阶段更清楚或消除重复；避免增加跳转层次、混合职责或写成难读的密集表达式。已清晰的代码可以不改。
5. **限定范围。** 默认聚焦当前改动；用户指定文件或目录时覆盖其全部手写 Go 代码和测试。保留用户修改，跳过第三方副本和生成产物。只执行任务授权的修改，既有业务缺陷单独报告；只读要求优先。

## 默认 Go 风格

- 名称与作用域、使用距离相称；省去上下文已明确的信息，同一概念一致命名。使用 MixedCaps 和一致缩写；接收者简短、类型相关且一致。
- 非空结构体多行声明，每个字段独占一行并分别写出类型，测试辅助类型同样处理。初始化在字段名能说明值的角色时采用具名写法，多条执行语句分别成行。
- 显式初始化通常用 `:=`，零值用 `var`；声明靠近使用位置，保留有意义的阶段分隔。
- imports 按标准库、项目内包、第三方依赖分组，省略空组；组间空行，组内交给格式工具排序。保留 cgo 前导注释与 `import "C"` 的关联。
- 返回值默认显式写出；命名结果仅在 defer／recover 依赖或有助于区分返回契约时保留。保留表达业务含义或固定求值时点的中间变量。
- 保留原因、契约、声明文档、版权与工具指令；普通排版交给 `gofmt`。这些是本技能默认约定，不是 Go 官方强制规则。

## 工作方式

理解完整函数、相关测试和必要调用方后，集中处理有明确阅读收益的候选，再复查最终代码及同类遗漏。对存疑项核实具体契约；仍不能确认等价时保留并简述原因，继续完成独立的局部清理。

遵循项目验证入口，对改动运行 `gofmt` 和相关检查。局部转换能由代码核对与已有测试支持时，复用这些证据；只有具体契约缺口才补最小测试，并先确认它在原实现上的行为。验证范围与实际变化相称，不顺带补齐整个函数的测试体系，相关输入未变时复用已完成的检查。

简要说明显著改进、实际验证和重要保留项。区分通过、跳过、既有失败与未验证路径；用验证输出支持结论，测试通过不能代替对清理效果的判断。
