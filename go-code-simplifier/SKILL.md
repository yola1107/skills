# Go Code Simplifier

改善 Go 代码的清晰度、一致性和可维护性，主动实施有阅读收益的清理：**行为等价 > 清晰度 > 简单 > 短**。

## 清理原则

1. **保持行为。** 保留功能、公开 API、输出、错误身份与文本、默认值、日志和测试契约。具体转换核对返回类型及失败部分值、求值次数与顺序、短路、nil／空集合、长度容量、共享与所有权，以及 defer、同步和资源生命周期。存疑候选保留并说明具体原因，继续完成独立的局部清理。
2. **遵循项目约定与 Go 惯例。** 读取适用的 AGENTS.md／CLAUDE.md、格式与 lint 配置，确认目标 module 的 Go 版本和构建条件。项目明确规则优先，未约定处以 [Effective Go](https://go.dev/doc/effective_go)、[Go Code Review Comments](https://go.dev/wiki/CodeReviewComments) 和 [Go Doc Comments](https://go.dev/doc/comment) 为依据；新语法和标准库 API 按目标版本判断。命名采用 MixedCaps 和一致缩写，排版交给 `gofmt`，标准库 imports 在首组；额外分组和字段布局按项目明确规则处理。
3. **改善清晰度。** 重点处理主流程嵌套、过宽作用域、返回转抄和无职责的跳转：
   - **控制流与作用域：** 用 early-return／continue 处理错误、边界和跳过路径，移除终止分支后的 else，让主流程平直；保留更清楚的并列分支，核对原返回值、循环尾部与退出目标。分支独占的临时值优先放入 if／switch 初始化语句，其他声明靠近使用阶段；保留快照、跨阶段状态和 defer 依赖。
     调用与函数均返回 error、成功路径返回 nil，且错误值只用于判断、记录和失败返回、没有外层或 defer 依赖时，采用 `if err := call(); err != nil { ...; return err }`，随后 `return nil`，将错误值限定在 if 内。
   - **返回与冗余：** 逐处检查 return 及其前面的赋值，删除结果转抄、多余判断、重复类型、无用存储与薄包装。命名结果仅在解释返回契约或 defer／recover 依赖时保留；短函数可使用清楚的裸返回，较长函数显式返回。直返须保持类型、错误与失败部分值；返回点数量不作为清理目标，合并返回以保留或收窄变量作用域为前提。
   - **命名与注释：** 按业务角色命名，详略与作用域和使用距离相称，同一概念一致称呼，省去上下文已表达的信息。保留 `i`、`err`、`ctx` 等惯用短名，接收者简短、类型相关且一致。删除废弃代码注释和函数体内明显的复述，修正过时说明；保留包与声明文档、原因、契约、版权、工具指令和阶段分隔。
4. **避免过度简化。** 保留解释业务或帮助调试的变量和抽象。重复逻辑只有在输入、失败、顺序与业务契约一致且属于同一职责时才合并；提取函数应解释处理阶段、隔离职责或消除重复，让调用处看得出流程与失败出口。已清晰的代码可以零修改。
5. **限定范围。** 默认聚焦当前改动；指定文件或目录时覆盖全部手写 Go 代码及测试，包括未改函数。保留用户修改，跳过 vendor、第三方副本和生成产物；生成代码通过源或生成流程更新。只读要求优先，业务修复、性能优化、依赖升级、架构调整和提交发布按各自授权处理。

## 执行流程

1. **定位范围。** 检查 Git 状态、暂存／未暂存和相关未跟踪内容，列全目标文件，确认项目规则与验证入口，以包含用户修改的实际状态为基线。
2. **理解与选择。** 按文件读完整函数，明确各路径的返回值、副作用和变量用途；按实际依赖补读测试、调用方或官方章节。先理清退出路径与作用域，再判断返回、冗余和结构，最后整理保留符号的命名，确定有阅读收益且等价的最终写法。
3. **集中修改。** 同一函数的关联变换一起完成，按职责连贯的批次实施并同步引用、注释。改名优先使用可用的语义工具，核对遮蔽、捕获和符号绑定；存疑项保留，继续独立候选。
4. **复核效果。** 对照完整函数和 diff，检查主流程、作用域、每处 return 及目标范围内同类遗漏，包括未改函数；结构变换产生的新机会在受影响函数内处理。撤销没有阅读收益或不能确认等价的本轮改动，保留用户修改。
5. **按变化验证。** 集中运行 `gofmt` 和受影响范围的项目测试、vet 或构建检查；陌生入口先核对初始化、TestMain 和外部资源隔离。实际涉及并发、同步或退出协作的变换运行相关 race。复用充分的代码核对与已有测试，只为具体契约缺口补最小测试；相关输入未变且没有新风险时复用已通过检查。
6. **简要交付。** 目标范围已覆盖、有收益且等价的候选已落实、本轮回归已解决后，说明显著改进、实际验证及重要保留项，保留理由具体到转换；区分既有失败、跳过与环境缺口。工具通过和改动数量不代替可读性与范围验收。
