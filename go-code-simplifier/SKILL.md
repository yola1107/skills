# Go Code Simplifier

让 Go 代码清楚、直接、容易维护。主动实施有阅读收益的清理，保持现有功能与行为；清晰度优先于代码行数，已清晰的代码可以保留。

默认处理当前改动；指定文件或目录时检查全部手写 Go 代码，包括测试和未改函数。遵循项目明确规则与目标 Go 版本，保留用户修改，跳过生成文件与第三方副本。只读要求优先，业务修复、性能优化和架构调整按各自任务处理。

代码风格以 [Effective Go](https://go.dev/doc/effective_go)、[Go Code Review Comments](https://go.dev/wiki/CodeReviewComments) 和 [Go Doc Comments](https://go.dev/doc/comment) 为依据；有疑问时查相关章节，不将个人偏好当作官方要求。新语法与标准库用法查目标版本的规范和 API 文档。

## 清理重点

- **命名。** 使用 MixedCaps 和一致的首字母缩写，名称描述业务角色，详略与作用域相称；同一概念一致命名，省去上下文已明确的信息。保留短循环中的 `i` 和惯用的 `err`、`ctx`。接收者简短、类型相关且一致；改名同步实际符号引用。
- **声明与返回。** 变量在合适的局部作用域声明，结合类型与零值选择 `:=` 或 `var`。删除无意义的转抄、重复类型和多余判断；保留解释业务、固定求值时点或被 defer 使用的变量。结果名称应有助于理解返回契约；裸返回仅用于返回值清楚的短函数，中等及较长函数显式列出返回值。
- **控制流。** 错误、边界和跳过路径先退出，让主流程平直。删除终止分支后的多余 else，简化冗余布尔表达式；并列业务分支按最容易理解的方式组织。
- **结构。** 清理无用代码、存储和薄包装，合并同一职责内契约一致的重复逻辑。提取函数应解释一个处理阶段或消除重复，保留有助于理解和调试的边界。
- **排版与注释。** 排版以 `gofmt` 输出为准；imports 分组间留空行，标准库在首组，其他分组遵循项目明确规则。包与导出声明的文档注释按 Go Doc Comments 编写。删除废弃代码注释和函数体内明显的复述，保留原因、契约、声明文档及工具指令。

## 工作方式

读完整函数、相关测试和必要调用方，理解现有职责后集中修改。保留公开 API、错误身份与失败部分值、求值顺序、nil／空集合、共享数据及资源收尾时点。存疑项保留并说明具体原因，继续完成独立的局部清理。

复查完整函数和 diff，检查主流程、命名、变量作用域及同类遗漏，撤销没有阅读收益的改动。运行 `gofmt` 和项目相关检查，复用已有测试；只有具体契约缺口才补最小测试，验证投入与实际改动相称。

范围内有收益且等价的清理落实后，简要说明显著改进、重要保留项和实际验证。检查通过与纯格式变化各自说明，不代替对代码可读性的判断。
