# Golang Code Simplifier

## 原则

1. **行为不变**：只改代码怎么写，不改代码做什么。不能证明等价的改动不做，写进报告。
2. **规范来源**：以项目规则（AGENTS.md、CLAUDE.md、lint 与 goimports 配置）为准，未规定的部分参考 Effective Go、Go Code Review Comments 和 Go Doc Comments。新语法、标准库 API 和循环变量语义，以文件实际生效的 Go 版本为准；排版交给 gofmt，空行与 import 分组按第 5 步。
3. **清晰胜过简短**：目标是让读者更快看懂，行数不是收益标准。已经清楚的代码保持原样。
4. **聚焦范围**：默认只处理当前改动涉及的函数；用户指定文件或目录时，处理其中全部手写代码。
5. **缺陷只报告**：发现的 bug 写进报告，代码不动。修复会改变行为，由用户决定。

## 红线

以下内容在改动前后必须一致，可能触碰它们的改动不做，列入报告「建议」：

- 导出标识符、接口方法集、struct 字段名与 tag、错误变量、错误文本与包装方式（`%v`/`%w`）。
- 函数签名中参数与结果的类型、个数和顺序。参数名和结果名不属于签名。
- 经反射或字符串引用的名字：框架按方法名注册的 handler、RPC 方法、ORM 表名与列名、配置 key。
- 副作用的种类、参数、次数和顺序：数据库、RPC、消息、文件、日志、指标。
- 锁的对象与临界区内的有效语句、goroutine 的启停、channel 的关闭、`defer` 的执行时机。
- 值的形态：nil 与空切片/空 map、切片共享的底层数组、浮点结果、是否 panic。

不处理生成代码（`// Code generated ... DO NOT EDIT.`）、`vendor/`、`testdata/`。不写新测试，不暂存，不提交。

## 工作流

```
- [ ] 1. 确定范围
- [ ] 2. 基线
- [ ] 3. 逐文件改写
- [ ] 4. 复查
- [ ] 5. 收尾格式
- [ ] 6. 最终验证与报告
```

**1. 确定范围。** 在仓库内运行 `go run <本 skill 目录>/scripts/scope.go [路径...]`。

- 不带路径时，范围是相对 HEAD 的改动和未跟踪文件。每个文件后标出范围：`changed:` 后是含改动行的函数，`outside functions:` 是函数外的改动行，`new file` 表示整个文件都在范围内。
- 脚本还会给出受影响的包、验证命令、疑似连接外部服务的测试，以及改完后需要转回 CRLF 的文件。

再读 `go.mod`（module 路径、go 版本）和项目规则文件。

**2. 基线。** 疑似外部依赖的测试，确认确实会连接数据库、网络或第三方服务后，用 `-skip` 排除。改动前跑一遍「验证」中的命令，记下结果。

装有 golangci-lint 时只读运行一次，项目有自己的配置就用项目的。输出中落在范围内的条目当作候选和缺陷线索，仍按第 3 步逐条判断。不要带 `--fix`，也不要运行 `golangci-lint fmt`：实测它会在 Windows 上破坏文件。

```bash
golangci-lint run -c <本 skill 目录>/scripts/golangci.yml <pkgs>
```

**3. 逐文件改写。** 每个文件依次做三件事：

1. 逐个读完范围内的函数，包括所有返回路径、`defer`、锁和副作用。按「缺陷扫描」记录发现，按「简化清单」找候选。
2. 只读当前函数就能证明等价的改动，直接做。等价性依赖函数外事实的改动（被调函数有无副作用、引用、接口实现），先查 [traps.md](references/traps.md) 对应小节并查证，再做，报告里写一句依据。有 gopls 时用它查引用和改名。查不清的列入「建议」。
3. 对所在包跑 `go build`（改了 `_test.go` 时用 `go vet`），编译错误当场修正。

每处改动都要能用一句话说清读者省了什么。

**4. 复查。** 重读每个改过的函数。以下情况仍然存在时补做，或在报告里写明不做的原因：

- 嵌套或分支长度超过「简化清单」第 1 项的上限。
- 声明离首次使用很远。
- 初始化后、首次读取前又被赋值。
- 只用一次、名字也没有信息量的变量。
- 「简化清单」第 6、8 项可以处理的返回值和名字。

**5. 收尾格式。** 对改过的文件依次执行：

1. **空行**：删除代码块开头和结尾的空行，保留分隔逻辑段落的单个空行；连续空行由 gofmt 压成一个。范围不是整个文件时，只处理改过的函数。
2. **import 分组**：项目没有 goimports/gci 配置时，分为标准库、本项目、第三方三组，组间空一行，组内顺序交给 gofmt。按以下顺序判断每个路径：
   - **本项目**：路径等于 module 路径，或以「module 路径/」开头。module 路径可能不含点（如 `go_manwugame`），所以先判断这一条。
   - **标准库**：剩下的路径中，第一段不含 `.`，且不是 `go.mod` 里的依赖模块。
   - **第三方**：其余全部。

   别名、`_`、`.` 导入保留原写法；`import "C"` 不动。构建工具链早于 Go 1.21 时不调整分组，见 traps.md「import」。
3. **gofmt**：运行 `gofmt -w <files>`，再把 scope.go 列出的文件转回 CRLF，命令见「验证」。

**6. 最终验证与报告。** 重跑基线命令逐项对比。出现新失败时，定位到具体改动，修正或撤回。最后按「报告模板」输出。

## 缺陷扫描

读每个函数时检查以下各项，命中的写进「发现」，代码不动：

- **锁**：
  - 没有 `defer` 解锁时，加锁到解锁之间有 `return`/`continue`/`break` 或 panic 路径。
  - 持有 `RLock` 时写 map、字段，或通过指针修改共享对象。
  - 同一数据由不同的锁保护，或有的地方不加锁。
  - 持有 `RLock` 时再申请同一把锁的 `Lock`。
  - 持锁期间做 I/O。
  - 同一字段混用 `atomic` 和直接读写。
- **错误**：
  - 出错只记日志，却返回成功（error 或错误码为 nil）。
  - `err` 没有检查就被覆盖。
  - `:=` 遮蔽了外层之后还要读的变量。
- **其他**：
  - 自定义 `Xxxf` 函数的格式符与参数不符。
  - 硬编码的密码、token、DSN、公网 IP。
  - 与代码矛盾的注释。
  - 写入可能为 nil 的 map。
  - 下标访问前没有检查长度。
  - 循环里的 `defer`。
  - 不会退出的 goroutine。

每条发现标注严重程度：**严重**（死锁、数据竞争、金额或状态错误、安全）、**一般**（错误被吞、日志错误、边界问题）、**轻微**（拼写、过时注释）。同时标注来源：HEAD 中已有的标「原有」，当前未提交改动引入的标「新引入」。

## 简化清单

按收益从高到低排列，示例见 [patterns.md](references/patterns.md)。

1. **控制流**：`if`/`for`/`switch`/`select` 嵌套不超过 3 层（函数体顶层为第 0 层，函数字面量重新计数），单个分支或循环体不超过约 20 行。超出时依次尝试：
   1. 错误、边界和要跳过的情况先 `return`/`continue`，再去掉其后的 `else`。`if/else` 是循环体（或函数）的最后一条语句时，`if ok {长} else {短}` 可以改成 `if !ok {短; continue}` 后接长分支。
   2. 同一变量有三个以上的比较分支时改成 `switch`；分支里有 `break` 时不改。
   3. 仍然超出时，把能起名的独立步骤提取为方法，只调用一次也可以。块内的 `return`/`continue`，以及块外还要读的变量，通过返回值带回。一长串字段赋值不提取。

   无论用哪种方法，加锁区域内的语句和锁的配对都保持不变。
2. **冗余**：无效赋值、恒真或恒假的条件、注释掉的代码、`len` 之前多余的 nil 判断、`delete` 之前多余的存在判断、首次读取前就被覆盖的初始化、结果没有被读取的计算。
3. **重复**：输入、副作用和顺序都相同的代码块，提取为函数；只是长得像的不合并。
4. **作用域**：把声明移到首次使用处或使用它的块内；只在 `if`/`switch` 里用的值放进初始化语句。只把 `var` 改成 `:=` 而位置不动，不算收紧作用域。
5. **错误处理**：
   - 错误分支里有日志等其他语句时，保持「在 `if` 内处理并显式 `return`」。`err` 只在 `if` 里用时，调用留在初始化语句里。
   - 错误分支里只有 `return err` 时，`if err != nil { return err }; return nil` 合并为 `return err`，前提是 `err` 的静态类型为 `error`。
6. **返回值**：
   - 有多个返回点或较长的函数，命名结果加裸 `return` 改为显式返回。结果名能说明同类型结果的含义时保留名字；`defer`/`recover` 读写结果时不动。
   - 删除结果属于改签名，只在函数未导出、调用点全在范围内、不用于满足接口也不作为函数值时做。
7. **新写法**（按文件生效的 Go 版本，前提见 traps.md「标准库替换」）：
   - 1.18：`any`、`strings.Cut`
   - 1.20：`strings.CutPrefix`
   - 1.21：`min`/`max`/`clear`、`slices`、`maps`
   - 1.22：`for i := range n`、去掉 `v := v`、`cmp.Or`
   - 1.23：`slices.Sorted(maps.Keys(m))`。注意 `maps.Keys` 返回迭代器，不是切片。
8. **命名**：目标是看名字就知道它装的是什么。只改局部变量、参数、结果名和未导出标识符；导出名和协议字段列入建议。
   - 替换 `data`、`info`、`tmp`、`ret`、`res`、`_x`、`ok1`/`ok2` 这类没有信息量的名字，以及名不副实的名字。
   - 名字长短与作用域相称。保留 `i`、`k`/`v`、`n`、`err`、`ctx`、`ok`、`mu`、`wg`、`req`/`resp` 等惯用短名。
   - 写法：
     - 用 MixedCaps，缩写整体同一大小写：`userID`、`URL`、`HTTP`。
     - 布尔值读起来像判断：`hasBet`。
     - 数值带上单位：`delayMs`。
     - 同一个概念只用一个名字。
     - 局部名不遮蔽内置名和函数里用到的包名。
   - receiver 名沿用项目写法（如 `this`）。
9. **注释**：删除复述代码的注释；保留解释原因和约束的注释，以及 `//go:`、`//nolint` 指令；改了条件或顺序后同步更新注释。

## 克制

- 一行只做一件事；需要嵌套闭包或长链式调用才能变短的代码，保持原样。
- 泛型、interface、option 模式只在多个调用点都受益时引入。
- 提取的函数要能起一个说清职责的名字，起不出来就不提取。
- 风格统一类改写（如 `interface{}` 改 `any`）只在本来就要改的函数里做。

## 验证

在 scope.go 输出的 module 目录下运行，`<pkgs>`、`<files>` 和 `-skip` 参数取自脚本输出：

```bash
gofmt -l <files>
go build <pkgs>
go vet <pkgs>
go test -skip '<外部依赖测试>' <pkgs>
go test -race -skip '<外部依赖测试>' <pkgs>   # 改动涉及锁、goroutine、channel 时；需要 cgo
```

- 项目配置了 golangci-lint 时一并运行。
- 缺少的工具不安装，记为未运行，不能写成通过。`-race` 在 Windows 上常因缺少 cgo 而无法运行，同样处理。
- 转回 CRLF：Unix 用 `unix2dos <file>`，PowerShell 用：

  ```powershell
  $p = (Resolve-Path <file>).Path
  [IO.File]::WriteAllText($p, ([IO.File]::ReadAllText($p) -replace "(?<!`r)`n", "`r`n"))
  ```

## 报告模板

```markdown
## 简化结果
范围：<N 个文件，M 个包>

### 发现（未修改）
- [严重][原有] `<文件>:<行>` `<函数>`：<问题>。影响：<后果>。修复方向：<一句话>

### 改动
- 汇总：<如"拉平嵌套 6 处、收紧作用域 9 处、改名 12 处">
- `<文件>` `<函数>`：<需要查证的改动>。依据：<查证了什么>

### 建议（未实施）
- `<位置>`：<建议>。原因：<触碰的红线或缺少的前提>

### 验证
- build / vet / test：基线 <结果> → 结束 <结果>
- 排除的测试：<名字及原因>；未运行：<检查项及原因>
```

有严重级别的发现时，在报告第一行提示。没有可做的改动时说明零改动，照常列出发现。
