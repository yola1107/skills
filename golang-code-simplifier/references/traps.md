# 等价陷阱

需要查证的改动，先查对应小节。每条给出改写成立的前提；前提不满足或无法确认时不做，列入报告「建议」。

## 删除代码

- **删除函数调用或表达式**：读过被调实现，确认无副作用（写状态、日志、指标、panic）。
- **删除未使用的声明**：搜索所有构建标签下的文件（`_linux.go`、`//go:build`），以及字符串形式的引用。包级变量的初始化表达式可能有副作用，如 `var _ = register()`。
- **删除常量**：同一 `const` 块里的 `iota` 会重新编号，需要保持取值时用 `_` 占位。
- **`var _ I = (*T)(nil)`** 是编译期接口断言，保留。

## 控制流

- **if-else 链改 `switch`**：分支内原本跳出外层 `for` 的 `break`，移进 `switch` 后只跳出 `switch`；`if f() == 1 {} else if f() == 2 {}` 调用多次 `f`，`switch f()` 只调用一次。
- **反转 if/else 并提前跳出**：`if c { A } else { B }` 改为 `if !c { B; continue }` 后接 `A`，要求这个 `if/else` 是循环体的最后一条语句；函数里用 `return` 时，它须是函数的最后一条语句，且返回值与原来走到末尾时相同。
- **提取函数**：
  - 移进新函数的 `defer` 在新函数返回时执行，比原来提前。
  - `recover()` 只在被 `defer` 直接调用的函数中生效。
  - 原代码中作用于原函数或外层循环的 `return`、`break`、`continue`，要通过返回值带回，所有路径结果不变。
  - 块内赋值、块外还要读的变量（包括 `err`）作为结果返回；块内修改了的外层变量，传指针或返回新值。
- **调整条件顺序**：`&&`/`||` 短路，交换后求值次数改变；保护后续访问的 nil 判断必须在前。

## 作用域

- **移动声明**：初始化表达式无副作用，原位置与新位置之间没有语句修改它读取的状态。
- **改用 `:=` 或放进 `if` 初始化语句**：原代码给外层 `err` 赋值、外层之后还读它时，改成 `:=` 会让外层 `err` 保持旧值。
- **把声明移进循环体**：变量的值需要跨迭代保留，或被取地址、被闭包或 goroutine 捕获时，留在循环外。
- **删除重复初始化**：两次初始化之间没有读取，也没有传给其他函数；第一次的表达式无副作用。

## 错误

- **合并为 `return err` 或 `return f()`**：静态类型必须是 `error`。若是 `*MyErr` 等具体类型，nil 指针装进 `error` 接口后不等于 nil。
- **`==` 改 `errors.Is`、类型断言改 `errors.As`**：会匹配被包装的错误，范围变宽，不做。

## 返回值

- **去掉结果名**：`func() (err error)` 与 `func() error` 类型相同，满足接口和反射注册（如 pitaya handler）不受影响。前提：
  - 没有 `defer`/`recover` 读写结果。
  - 裸 `return` 全部改成显式返回，返回的是该处结果变量的当前值。
  - 结果名在函数体里当普通变量读写时，改成局部变量并保持读写顺序。
- **删除结果**：调用方要同步修改；函数作为值传递或用于满足接口时不能删除。

## import

- **调整分组和顺序**：包初始化顺序由构建所用的工具链决定，与 `go.mod` 的 `go` 版本无关。Go 1.21 及以后的工具链按导入路径排序初始化，书写顺序不影响；更早的工具链下调整顺序可能改变 `init` 的执行顺序。
- **`import "C"`** 必须紧跟 cgo 注释，保持单独声明。

## 值的形态

- **空集合写法互换**：`var s []T`、`[]T{}`、`make([]T, 0)` 的 `s == nil` 结果不同，JSON 编码分别为 `null`、`[]`、`[]`。值会被返回、序列化或比较时保持原写法；向 nil map 写入会 panic。
- **`append` 与切片共享**：`b := a[:n]; b = append(b, x)` 可能改写 `a[n]`。`slices.Delete` 在 1.22+ 会把尾部空出的元素置零。
- **去掉类型转换**：`float64(1)/3` 去掉转换后变成整数除法；只对整数和字符串去掉同类型转换。

## 标准库替换

- **生效版本**：默认取 `go.mod` 的 `go` 指令；文件带 `//go:build go1.N` 时按该版本。作用域内有自定义的 `any`、`min`、`max`、`clear` 时不替换。
- **`strings.Cut`**：未找到分隔符时返回 `s, "", false`；原代码未找到时返回别的值或会 panic，就不等价。
- **`min`/`max`**：浮点参数中有 NaN 时结果为 NaN，与手写比较不同。参数可能是浮点时保持原写法。
- **`cmp.Or`**：所有参数先全部求值，没有短路。参数有函数调用时保持原写法。
- **`clear`**：`clear(m)` 清空所有持有者看到的 map，`m = make(...)` 只换当前变量；`clear(s)` 只把元素置零，长度不变。
- **排序**：`sort.Slice` 对应 `slices.SortFunc`（都不稳定），`sort.SliceStable` 对应 `slices.SortStableFunc`；比较函数在相等时必须返回 0。
- **`for i := range n`**：`n` 和 `i` 在循环中不被修改；`i` 的类型变为 `n` 的类型，`for i := byte(0); i < 10; i++` 改写后 `i` 是 `int`。
- **删除 `v := v`**：文件生效版本为 1.22+，循环变量由循环头部的 `:=` 声明。

## 命名

- **查引用**：除了标识符本身，还要搜字符串形式、struct tag、模板、配置文件、其他构建标签下的文件。
- **方法改名**：确认不用于满足接口。`x.(interface{ reset() })` 在方法改名后静默返回 false。
- **未导出字段改名**：字段名会出现在 `%+v` 的日志输出里，gob、反射拷贝也可能依赖它。
- **新名字**：不能与函数内之后还要用到的包名、内置名或外层变量同名。遮蔽同类型的外层变量时能编译通过，但读写对象变了。
- **参数改名**：不影响调用方和接口实现；同步修改 doc comment 中提到的参数名。
- **合并重复调用为局部变量**：被调函数无副作用，两次调用之间返回值不变。

## 并发

- **在加锁的函数里调整控制流**：没有 `defer` 解锁时，新增的 `return`、`continue`、`break` 只能在加锁之前或解锁之后。原代码已在锁内提前返回的，是缺陷，只报告。
- **移动代码进出临界区**：`Lock()` 与 `Unlock()` 之间的有效语句和顺序不变；改成 `defer mu.Unlock()` 会把后续代码也纳入临界区。
- **删除临界区内的死计算**：只读取共享数据、写入之后没人读的局部变量时可以删除，被调函数须无副作用。这只缩短持锁时间。
- **值接收者与指针接收者互换**：会复制 `sync.Mutex` 等字段并改变方法集，不做。
- **goroutine 捕获的变量**：抽取或内联闭包后，捕获的仍是同一个变量。
