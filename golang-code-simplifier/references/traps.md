# 等价陷阱

B 级改动前查对应小节。每条给出改写成立的前提；前提不满足或无法确认时降为 C 级。

## 删除代码

- **删除函数调用或表达式**：读过被调实现，确认无副作用（写状态、日志、指标、panic）。
- **删除未使用的声明**：搜索所有构建标签下的文件（`_linux.go`、`//go:build` 等），以及字符串形式的引用。
- **删除包级变量**：初始化表达式无副作用。`var _ = register()` 无人引用，但会在包初始化时执行。
- **删除常量**：注意同一 `const` 块里的 `iota`。`const (a = iota; b; c)` 删除 `a` 后，`b` 从 1 变成 0；需要保持取值时用 `_` 占位。
- **删除 `var _ I = (*T)(nil)`**：这是编译期接口断言，保留。

## 控制流

- **if-else 链改 `switch`**：
  - 分支内的 `break` 原本跳出外层 `for`，移进 `switch` 后只跳出 `switch`。含 `break` 的链保持原样，或改用带标签的 `break`。
  - `if f() == 1 {} else if f() == 2 {}` 每个分支各调用一次 `f`，`switch f()` 只调用一次。比较对象是函数调用时保持原样。
- **提取函数**：
  - 移进新函数的 `defer` 在新函数返回时执行，比原来提前。
  - `recover()` 只在被 `defer` 直接调用的函数中生效，包进辅助函数后不再捕获 panic。
  - 原代码中的 `return`、`break`、`continue`、`goto` 作用于原函数或外层循环，提取后要通过返回值显式传回，所有路径结果不变。
- **调整条件顺序**：`&&`/`||` 短路，交换后求值次数改变；含函数调用、map 访问可能 panic 的 nil 判断时保持原顺序。

## 作用域

- **移动声明位置**：初始化表达式无副作用，且原位置与新位置之间没有语句修改它读取的状态。
- **改用 `:=` 或放进 `if` 初始化语句**：确认没有遮蔽外层同名变量。原代码给外层 `err` 赋值、外层后续还读它时，改成 `:=` 会让外层 `err` 保持旧值。
- **把声明移进循环体**：原来在循环外声明的变量是所有迭代共享的一个变量，移进循环后每轮一个新变量。变量的值需要跨迭代保留（如上一轮的 `otherpid`），或被取地址、被闭包或 goroutine 捕获时，保持在循环外。
- **删除重复初始化**：确认两次初始化之间没有读取该变量，也没有把它传给其他函数或存入其他结构；第一次初始化的表达式没有副作用。

## 错误

- **`if err != nil { return err }; return nil` 合并为 `return err` 或 `return f()`**：`err` 或 `f` 的结果静态类型必须是 `error`。若是 `*MyErr` 等具体类型，nil 指针装进 `error` 接口后不等于 nil，调用方的 `err != nil` 从 false 变为 true。
- **`err == ErrX` 改为 `errors.Is`，类型断言改为 `errors.As`**：会匹配被包装的错误，匹配范围变宽。属于 C 级。
- **错误包装与文本**：`%v` 改 `%w` 会让调用方的 `errors.Is`/`errors.As` 开始匹配内部错误，`%w` 改 `%v` 则相反；改动文本会影响日志检索和按字符串比较的调用方。已有的包装方式和文本都属于红线，不做统一。

## 返回值

- **去掉命名结果或结果名**：结果名不属于函数类型，`func() (err error)` 与 `func() error` 类型相同，满足接口、赋值给函数类型变量、按类型反射注册（如 pitaya handler）都不受影响。前提：
  - 没有 `defer`/`recover` 读取或修改结果。`defer func() { if r := recover(); r != nil { err = ... } }()` 依赖命名结果把 panic 转成错误，去掉后无法赋值。
  - 裸 `return` 全部改成显式返回，且每个返回点返回的是该处结果变量的当前值。原代码先给结果赋值、中间又有修改时，显式返回要用修改后的值。
  - 结果名在函数体内没有被当作普通变量读写；有的话，改成局部变量并保持读写顺序。
- **删除结果**：调用方式 `a, b := f()` 需要同步修改；函数作为值传递（`var fn func() (int, error) = f`、回调参数）或用于满足接口时不能删除。

## import

- **调整分组和顺序**：包初始化顺序由构建所用的工具链决定，与 `go.mod` 的 `go` 版本无关。Go 1.21 及以后的工具链按导入路径排序初始化依赖，import 的书写顺序不影响初始化；更早的工具链下调整顺序可能改变 `init` 的执行顺序。
- **别名与特殊导入**：别名、`_`、`.` 导入只调整所在分组，不改写法；`import "C"` 必须紧跟 cgo 注释，保持单独声明。

## 值的形态

- **空集合初始化互换**：`var s []T`、`[]T{}`、`make([]T, 0)` 的 `s == nil`、`reflect.DeepEqual` 结果不同，JSON 编码分别为 `null`、`[]`、`[]`。map 同理，且向 nil map 写入会 panic。值会被返回、序列化或比较时保持原写法。
- **`append` 与切片共享**：`b := a[:n]; b = append(b, x)` 可能改写 `a[n]`。替换成 `slices.Insert`、`slices.Delete`、新建切片等写法时，确认底层数组共享关系与原来一致。`slices.Delete` 在 1.22+ 会把尾部空出的元素置零。
- **`fmt.Sprint(x)` 改为 `x.String()`**：`x` 为 nil 指针时前者输出 `<nil>`，后者可能 panic。`fmt.Sprintf("%d", x)` 改为 `strconv.Itoa(x)` 要求 `x` 恰好是 `int`。
- **去掉同类型转换**：`float64(1)/3` 得 0.333，去掉转换后 `1/3` 得 0；浮点表达式外的 `float64(x*y)` 阻止编译器融合乘加，去掉后在 arm64 等平台结果可能不同。只对整数、字符串去掉多余转换。

## 标准库替换

- **生效版本**：默认取 `go.mod` 的 `go` 指令；文件带 `//go:build go1.N` 时按该版本处理。
- **同名遮蔽**：作用域内有自定义的 `any`、`min`、`max`、`clear` 时，替换后指向的是自定义版本。
- **`strings.Cut`**：未找到分隔符时返回 `s, "", false`。原代码用 `strings.SplitN(s, sep, 2)[1]` 时缺分隔符会 panic，改用 `Cut` 后不再 panic，属于行为变化。
- **`min`/`max`**：参数为浮点时，任一参数为 NaN 则结果为 NaN，`min(-0.0, 0.0)` 为 -0.0。手写的 `if a < b { return a }; return b` 在 `a` 为 NaN 时返回 `b`。参数可能是浮点时保持原写法。
- **`cmp.Or`**：所有参数在调用前全部求值，没有短路。参数含函数调用或有副作用时保持原写法。
- **`clear`**：
  - `clear(m)` 清空原 map，所有持有它的地方都受影响；`m = make(map[K]V)` 只换当前变量。两者不能互换。
  - `for k := range m { delete(m, k) }` 改 `clear(m)`：键含浮点 NaN 时 `clear` 会多删除这些键。
  - `clear(s)` 只把元素置零，长度不变，不等于 `s = s[:0]`。
- **排序**：`sort.Slice` 不稳定、`sort.SliceStable` 稳定；替换为 `slices.SortFunc`（不稳定）或 `slices.SortStableFunc`（稳定）时保持一致。`less` 改 `cmp` 时，相等情况必须返回 0。
- **`for i := range n`**：
  - `n` 在循环中不变。`range n` 只在进入循环前求值一次，原循环每轮判断 `i < n`。
  - 循环体不修改 `i`。
  - `i` 的类型不变。`for i := byte(0); i < 10; i++` 中 `i` 是 `byte`，`for i := range 10` 中 `i` 是 `int`。
- **删除 `v := v`**：
  - 文件生效版本为 1.22+。
  - 循环变量由循环头部的 `:=` 声明。`for _, v = range` 复用外层变量，删除副本后闭包全部看到最后一个值。
  - 副本声明之前没有对循环变量取地址或在闭包中引用。

## 命名

- **查引用**：除了标识符本身，还要搜字符串形式、struct tag、模板、配置文件、其他构建标签下的文件。
- **方法改名**：确认方法不用于满足接口，也不被运行时类型断言使用。`x.(interface{ reset() })` 在方法改名后静默返回 false，编译器不报错。
- **框架反射注册**：pitaya、gRPC、net/rpc 等框架按方法名注册 handler 或路由，导出方法改名、改签名都会让调用方失效，即使仓库内没有直接引用。
- **未导出字段改名**：字段名会出现在 `%+v`、`%#v` 的输出里，检查打印该结构体的日志；gob、反射拷贝等也可能依赖字段名。
- **receiver、局部变量改名**：确认不与函数体内其他标识符、闭包捕获的变量冲突。

## 并发

- **值接收者与指针接收者互换**：值接收者会复制整个结构体，含 `sync.Mutex`、`sync.WaitGroup`、`atomic` 字段时复制会出错；方法集变化还会影响接口满足关系。属于 C 级。
- **在加锁的函数里调整控制流**：没有 `defer` 解锁时，新增的提前 `return`、`continue`、`break` 不能落在 `Lock()` 与 `Unlock()` 之间；把 `if` 展平为提前返回时，确认返回点在加锁之前或解锁之后。原代码已在锁内提前返回的，属于缺陷，不顺手修复。
- **移动代码进出临界区**：`Lock()` 与 `Unlock()` 之间的代码范围不变；把 `mu.Lock(); ...; mu.Unlock()` 改为 `defer mu.Unlock()` 会把后续代码也纳入临界区。
- **goroutine 中的变量捕获**：抽取或内联闭包时，确认捕获的仍是同一个变量，而不是在启动时求值的副本，反之亦然。

## 验证

- **只打印、不断言的测试**不能证明等价。
- **竞态**：涉及并发的改动跑 `go test -race`，它依赖 cgo（Windows 需要 gcc）；跑不了时在报告中注明。
- **gofmt 重排**：删除声明块中的一行可能让前后对齐区域合并，gofmt 会改动整块的空白。必要时在原位置保留空行，避免 diff 噪音。
- **平台相关行为**：浮点融合乘加、构建标签文件只在对应平台编译，本机测试通过不代表其他平台等价。
