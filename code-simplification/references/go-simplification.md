# Go 行为等价简化

在目标项目的 Go 版本、构建条件和业务契约下，检查命名、表达式、控制流、重复规则及职责表达。以下内容可独立使用；选择能说明阅读收益并证明等价的变换，不追求改动数量或固定行数。

## 范围与准备

- 阅读适用 AGENTS.md、目标范围和当前 diff，包括相关暂存、未暂存及未跟踪文件，以用户现有改动为基线。
- 指定目录时检查其中手写 Go 代码和测试；生成产物通过源/生成流程维护，第三方副本不因位置相邻就进入清理范围。
- 确认所属 go.mod、支持的语言与工具链版本、平台、标签及现有工作区。使用新语法或标准库 API 前检查兼容性；清理不自动升级依赖或添加跨 module 的 replace/go.work。

## 命名、声明和局部表达

- 名称表达角色，长度与作用域相称。修正误导或混淆的名称，保留 ctx、err、cfg、i 等语境清楚的惯用名称；使用 MixedCaps 和一致的缩写。不为了风格修改协议字段、数据库列名或公开 API。
- 接收者名简短且与类型相关，同类型在范围内保持一致。改名前查全部赋值、用途、遮蔽和闭包，保持接收者类型与方法集。
- 变量靠近所属处理阶段和首次使用处声明；保留有意义的分组和业务概念。移动声明前检查初始化时点、随机调用、跨迭代状态、类型转换和副作用。
- 删除纯转抄、冗余比较和无意义转换；保留固定求值时点、表达单位/角色或简化复杂表达式的变量。右侧值未被读取不代表求值可以删除。
- 按项目约定整理 import 和空行。删除注释中的显然复述，保留原因、契约、版权、编译/生成/检查指令及 Example 输出断言。无符号引用的 import 仍可能有 init 或注册副作用。

## 控制流、返回值与错误

终止分支可以 early return/continue，正常流程放到外层；保留更清楚的并列分支。移除 else 前检查 if-init 变量的作用域。循环中的 continue/break 还要核对尾部工作、post、标签，以及 switch/select 的实际退出目标。

有返回值的函数优先显式返回；命名结果在 defer/recover 使用或有助于区分同类型返回含义时保留。直返前核对返回类型、隐式转换、错误优先级和部分结果。

以下代码不能机械改成 `return load()`，因为它有意丢弃失败时的部分值：

```go
value, err := load()
if err != nil {
    return 0, err
}
return value, nil
```

以下局部赋值也不能省略，即使函数没有命名结果，defer 闭包仍会读取 err：

```go
func execute() error {
    var err error
    defer func() { record(err) }()
    err = work()
    return err
}
```

相反，只有无额外职责的 `value, err := load(); return value, err`，且类型转换等条件不变时，才可直接返回。

保持 sentinel identity、错误链、errors.Is/As 分类、首个错误和部分结果。新增包装、吞错、重试、日志、校验或 recover 都可能改变行为，不能当作附带简化。

## 类型、共享关系和求值

| 边界 | 简化时保留的内容 |
| --- | --- |
| interface 与 nil | nil interface 与装入 typed nil 后的非 nil interface 不等价；删除变量时仍要保留原类型转换 |
| slice/map/pointer | nil/空集合、缺失键/零值、长度/容量、顺序、重复项、底层数组和别名共享 |
| 数值 | 整数宽度与溢出、常量类型、浮点分组、NaN/正负零、金额单位与舍入 |
| 表达式 | 调用次数和顺序、短路、随机/时间读取、惰性或条件执行 |
| 函数与类型 | 接收者类型、方法集、类型别名身份、接口实现及反射/序列化契约 |

将随机结果提前保存、把惰性分支参数改成预先求值、合并重复但有副作用的调用，都需要证明等价。金额和概率代码的表达式改写不能只靠编译或少量 happy-path 测试判断。

## 包装、重复和职责

- 删除包装前确认它不承担错误转换、日志、同步、事务、资源收尾、公开兼容或注册职责。单行包装也可能有明确价值。
- 同形代码只有在输入、失败、顺序和业务契约相同、并且属于同一责任方时才合并。提取到通用包不能成为转移业务规则的理由。
- 删除无独立语义的派生存储前，确认其是否实际承担快照、缓存或恢复证据；不要把可推导与可随时重算混为一谈。
- 新 helper 或接口应消除当前重复、隔离明确职责或降低调用方复杂度，不为将来扩展、mock 方便、函数长度或复杂度分数新增层次。
- 内部迁移能一起完成时同步调用方、测试和文档；公开符号缺少仓内引用不能证明没有外部消费者。别名与兼容包装只为真实兼容要求保留。

## 锁、defer 与生命周期

- 保持锁范围、锁顺序、锁内调用和不变量；提取函数不能让 Unlock/Close/rollback 比原来更早或更晚发生。
- 区分 `defer cleanup(value)` 的登记时求值与闭包执行时读取。将循环体移进函数可能提前执行 defer，不能仅为缩短函数就认定等价。
- 保持 goroutine 的创建、取消、等待，channel 的收发、关闭和背压，以及资源初始化失败后的回滚顺序。
- 不复制带锁或资源所有权的结构；不自动把同步代码改成异步，也不把 Mutex 换成 RWMutex/atomic 作为清理。
- 保持 panic/recover、外部 I/O、日志以及请求准入后的完成契约。改变计时器或重试结构时核对起算点、截止时间与未知结果处理。

## 工具与验证

优先使用已有语义工具核对符号、引用、实现和方法集，并预览编辑范围。文本替换或 AST 名称匹配不证明符号身份；还需检查构建条件、生成输入、反射和外部消费者。工具不可用时完成能确认的工作并说明限制，不自动安装或改变工作区。

每个相关批次完成后，比较完整函数与调用链，分别检查阅读收益和行为等价。无法证明的候选保留并写明原因；回退仅针对本轮改动，保留用户工作。

先检查 TestMain、包初始化、环境变量、fixture 和清理行为，确保外部资源隔离。按项目入口运行 gofmt、受影响测试和 go vet；并发访问、同步或退出协作变化时补相应 race 验证。独立 module 分别检查，不把交叉编译、跳过用例或历史记录当作本次执行通过。

测试允许同步符号、导入和位置，保持输入、断言含义、失败/跳过条件、setup/cleanup 和同步语义。仅为实际行为风险补用例，不为纯命名、格式和等价直返另建套件，不增加生产全局开关或扩大接口来方便测试。

复审完整范围，逐项落实候选或说明保留理由。复用本轮输入未变的有效验证结果，仅因新改动、失败或具体风险追加检查；性能或大样本统计验证按任务与项目要求选择。

语言行为以目标版本的 [Go 规范](https://go.dev/ref/spec) 为准；具体类型的约束查对应版本的标准库或依赖 API。
