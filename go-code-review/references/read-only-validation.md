# 只读验证边界

在执行 Git 查询、加载 module 或运行代码前阅读。只读指保留原工作树、索引和 HEAD，并遵守外部资源授权；复制目录和命令行选项都不是操作系统级沙箱。

## Git 查询

先检查适用 Git 配置、属性和环境中可能执行外部程序的设置。可信环境下读取工作树差异可使用：

```sh
git --no-pager --no-optional-locks -c core.fsmonitor=false diff --no-ext-diff --no-textconv
```

暂存差异在 `diff` 后增加 `--cached`；PR／分支按已固定的基线选择范围。以上示例不是完整范围发现命令，不能漏掉相关未跟踪文件、未暂存内容或指定目录中的未改函数。

`--no-optional-locks` 只抑制需要锁的可选操作；`--no-ext-diff` 和 `--no-textconv` 分别禁用外部差异程序与文本转换，`--no-pager` 禁用分页程序，`core.fsmonitor=false` 禁用文件系统监视器。它们不禁止所有外部执行：工作树转换仍可能运行 clean／process 过滤器。发现这类设置或无法确认配置可信时，改用已验证的隔离环境或直接读取文件与对象内容，不在原树执行可能写入的查询。

不要通过修改原仓库配置来获得上述边界。参考 [Git 选项](https://git-scm.com/docs/git)、[diff 选项](https://git-scm.com/docs/git-diff) 与 [属性和过滤器](https://git-scm.com/docs/gitattributes)。

## 选择与建立验证环境

先静态追踪契约与候选，再按风险选择最小必要检查；不为每次只读审核无条件搭建新环境。优先复用项目已有、确认覆盖受审状态的隔离入口。加载 module 或执行代码的检查，包括 go test、vet、race 和项目静态检查，均在隔离副本运行。

副本须反映受审状态、相关未跟踪文件和构建必需文件。核对实际路径边界：符号链接、硬链接、`.git` 指针、GOWORK 和本地 replace／go.work 路径不能把检查写回原目录或共享 Git 元数据。普通 worktree 共享 Git 元数据，不自动满足该要求。

可将已存在的本地路径一致映射到内容及相关链接共享关系等价的独立副本，核实实际解析的 module／文件位置并记录映射；不新增依赖关系、替换依赖内容或版本、改变 module/vendor 模式来制造通过。无法可靠映射时停止依赖该环境的检查，说明缺口并继续静态审核，不反复改造依赖环境。

## 执行与收尾

执行前确认 GOFLAGS、GOWORK、实际工具链、module/vendor 模式、包初始化、TestMain、fixture／产物写入和外部资源。绝对路径、共享缓存、凭据和网络服务不会因复制目录而自动隔离；服务级验证也须在已有授权和隔离边界内执行，无法确认时不运行。

记录运行位置、命令、环境差异、结果及实际覆盖。需要归因时保留同条件基线；无法判断来源的失败标为未归因。结束后复核原工作树、索引及 HEAD，区分本轮副作用和并行用户改动，不回滚用户工作。未执行、失败和因环境受限跳过的检查分别报告，不用交叉编译、跳过用例或工具退出码替代路径覆盖证据。
